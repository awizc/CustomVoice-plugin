# CustomVoice

BetterDiscord용 음성·방송 플러그인과 Windows native 캡처 도우미입니다.
이 배포본의 저장소 및 업데이트 경로는 **awizc/CustomVoice-plugin**이며 공개 저장소로 운영합니다.
기존 작성자 정보와 번들에 포함된 저작권 표시는 유지합니다.

## 설치

[Releases](https://github.com/awizc/CustomVoice-plugin/releases)에서 Windows x64 ZIP을 받습니다.
압축을 **전부** 풀고 Discord를 트레이에서 완전히 종료한 뒤 `Install.cmd`를 실행합니다.
일반 사용자는 Node.js나 .NET을 따로 설치할 필요가 없습니다.
`CustomVoice.plugin.js`와 `CustomVoice.native` 폴더가 함께 필요하며 기존 설정은 유지합니다.

## 1.1.22 인코딩·창 모드 개선

- **플러그인 1.1.22 / native 1.1.15**입니다. 통화 중 파일을 덮어쓰지 않으며 native 업데이트는 Discord 완전 종료 후 적용됩니다.
- 알탭 복귀는 목표 FPS의 75%에서 두 통계 구간에 걸쳐 올라갑니다. 이미 안정적으로 동작한 속도가 더 낮으면 그 속도부터 시작합니다. 중복 크기/모드 이벤트는 회복을 초기화하지 않습니다.
- WebRTC 해상도 적응에 최대 6초를 주되, 실제 캡처·버퍼 과부하에는 즉시 대응합니다. 정상 크기/입력 조건에서 측정한 인코더 이력은 GPU·드라이버·브라우저·해상도·FPS별로 최대 14일 저장합니다. 네트워크 문제는 인코더 평가에서 제외합니다.
- GPU 변환/복사 시간, 버퍼 보유 시간, 수신측 프리즈/지터를 진단 로그에 추가했습니다. GPU 측정은 대기나 강제 flush 없이 수행합니다.
- osu!, SDL, GLFW, Unity, Unreal, LWJGL 게임 창은 창 모드에서도 게임 후크를 시도합니다. 보더리스와 전체화면의 기존 복귀 경로를 유지하며 FPS만 바꾸면 GPU 변환기를 다시 생성하지 않습니다. 게임 캡처 중 불필요한 WGC 프레임 보유와 마지막 프레임 저장의 중복 flush를 줄였습니다.
- 별도 **D3D11 → NVENC H.264 → LiveKit** 엔진을 포함합니다. P1/초저지연, B 프레임·lookahead 없음, 제한된 GPU 프레임 큐, 혼잡 제어, RTP pacing, NACK/PLI, 브라우저 인코더 복귀 경로를 구현했습니다. 로컬 미리보기는 15 FPS로 분리합니다.
- **별도 엔진은 서버 기능 추가 전에는 활성화되지 않습니다.** 기존 음성 identity를 재사용하지 않습니다. 서버 관리자용 [API 계약 및 배포 조건](SERVER-NATIVE-SCREEN.md), [참조 구현](server/native-screen-service.cjs)을 함께 제공합니다. 기존 서버에서도 위의 일반 캡처·WebRTC 개선은 적용됩니다.
- 검증: JS 회귀/서버 권한 테스트, 소유한 합성 GPU 텍스처의 NVENC 360p·1080p·1440p 출력/비트레이트 변경/키프레임/디코드, H.264 WebRTC 로컬 RTP 송수신. 실제 게임 및 두 PC의 운영 서버 송수신 시험은 수행하지 않았습니다. 모든 환경에서 165 FPS를 보장하는 변경은 아닙니다.

개발 빌드에는 .NET 9 SDK와 Go 1.27.3 이상이 필요합니다. `package.ps1 -Dotnet <dotnet.exe> -Go <go.exe> -SkipCapabilityCheck`로 캡처 실행 없이 패키지를 만들 수 있습니다.

## 1.1.21 반복 알탭·지속 과부하 대응

- **플러그인 1.1.21 / native 1.1.14**입니다. 기존 native 1.1.14는 그대로 사용하며 통화 종료 후 플러그인 자동 업데이트로 적용합니다.
- 로그에서 캡처는 165 FPS인데 WebRTC가 `cpu` 제한으로 약 90~105 FPS를 보내는 구간을 확인했습니다. 기존 해상도 유지 정책이 프레임률을 줄이는 경로였습니다.
- **60 FPS 이상은 움직임 우선**, 15·30 FPS는 선명도 우선으로 설정합니다. 고FPS 방송은 지속 과부하에서 WebRTC가 송출 해상도를 일시 조절하며, 여유가 생기면 원래 해상도로 복구할 수 있습니다. 선택한 캡처 크기·FPS·비트레이트 한도는 유지합니다. 장치와 네트워크의 처리 한도를 넘는 FPS를 보장하지는 않습니다.
- 중간 FPS에 머물러도 안정적인 출력이 이어지면 속도를 단계적으로 올려 확인합니다. 실패하면 이전 속도로 돌아가고 재시도를 15→30→60초 간격으로 늦춥니다. 네트워크 혼잡·캡처 대기·오래된 통계는 복구 시도의 근거로 사용하지 않습니다.
- `powerEfficientEncoder=false`를 직렬 CPU 인코더로 단정하지 않습니다. 평균 인코딩 지연의 역수를 FPS 상한으로 삼는 대신 실제 처리량과 복구 결과를 사용합니다.
- 송신자 교체·방송 종료와 겹친 늦은 통계 및 설정 적용을 차단합니다. 캡처의 최신 프레임만 보관하는 제한된 큐와 기존 송수신 정리 동작을 유지합니다.
- 송출 모니터에 **실제 송출 해상도 / 인코딩 부하 / 네트워크 제한 / FPS 복구 상태**를 표시합니다. 캡처 FPS는 native 출력 기준으로 구분하며 로그에 WebRTC 입력, 비트레이트, 패킷 송신 지연, 제한 시간 비율을 함께 기록합니다.
- 합성 테스트로 10분간 100 FPS 과부하 후 165 FPS 복구, 반복 전환, 네트워크 혼잡, 송신자 교체를 검증했습니다. 실제 게임과 두 PC 송수신 검증은 수행하지 않았습니다.

설계 근거: [W3C의 해상도·프레임률 우선 정책](https://www.w3.org/TR/mst-content-hint/#degradation-preference-when-encoding), [WebRTC의 과부하 적응](https://webrtc.googlesource.com/src/+/1856b2ce71700faceb9f3dd8dfe7f24e17987e57/video/g3doc/adaptation.md), [인코더 효율 및 제한 통계 정의](https://www.w3.org/TR/webrtc-stats/#dom-rtcoutboundrtpstreamstats-powerefficientencoder).

## 1.1.20 송출 FPS 저하 후 복구 수정

- **플러그인 1.1.20 / native 1.1.14**입니다. 기존 native 1.1.14 사용자는 플러그인 자동 업데이트만으로 적용됩니다.
- 일시적인 인코딩 지연으로 송출 제한이 165에서 3.18 FPS까지 급락한 뒤 회복하지 않는 문제를 수정했습니다. 부하 조정 한 번에 FPS가 절반 미만으로 떨어지지 않으며, 지속적인 과부하에는 단계적으로 대응합니다.
- 낮은 FPS의 정수 프레임 측정 오차를 실제 통계 수집 간격에 맞춰 처리합니다. WebRTC가 하드웨어 인코더 여부를 알려주지 않을 때 처리 시간만으로 복구 상한을 정하지 않습니다.
- 로그 조건을 재현한 자동 테스트로 저속 구간에서 설정 FPS까지의 복구, native 속도 전달, 지속 과부하·프레임 중단 시 보호 동작을 검증했습니다. 실제 게임과 두 PC 송수신 검증은 수행하지 않았습니다.

## 1.1.19 업데이트 설치 예약 완료 응답 수정

- **플러그인 1.1.19 / native 1.1.14**입니다. 1.1.18의 모든 UI 개선을 포함합니다.
- 다운로드가 끝나도 종료 대기 설치 도우미가 응답 파이프를 상속해 업데이트 요청이 끝나지 않는 Windows 문제를 수정했습니다. 도우미는 숨겨진 독립 프로세스로 실행합니다.
- 이전 native에서 처음 업데이트할 때도 설치 상태를 별도로 확인해 다운로드 완료와 재시작 안내를 바로 표시합니다.
- 실제 숨겨진 테스트 프로세스로 요청 종료 후 설치 대기 프로세스가 유지되고 응답 파이프는 닫히는 것을 검증했습니다. Discord나 게임은 조작하지 않았습니다.

## 1.1.18 Discord UI 정리

- CustomVoice의 채널·참여자 목록, 프로필·방송 미리보기, 시청 화면, 설정창과 송출 모니터의 글꼴·줄높이·간격·포커스 표시를 정리했습니다. Discord 테마 색상과 기본 글꼴을 사용합니다.
- 설정을 계정과 연결 / 음성 / 화면 공유 / 연결과 알림 / 업데이트로 구분했습니다. 고급 서버 주소는 접어 두고, 저장 버튼과 처리 결과는 하단에 표시합니다.
- 공유 선택창에 창 이름 검색과 닫기 버튼을 추가했습니다. 긴 앱 이름과 아이콘을 같은 기준선에 맞추고 작은 창에서는 한 열로 표시합니다.
- 앱 탭은 **앱 소리 공유**, 전체 화면 탭은 **시스템 소리 공유**로 표시하며 실제 전달 범위를 설명합니다. 소리를 끄는 옵션은 마이크 음소거와 별개입니다.
- 플러그인 **1.1.18 / native 1.1.13**입니다. 1.1.17의 토큰 없는 GitHub 자동 업데이트를 포함합니다.
- 검증은 메모리 DOM과 자동 테스트로 진행했습니다. 실제 Discord 화면 조작·캡처는 수행하지 않았습니다.

## 1.1.17 공개 GitHub 자동 업데이트

- **플러그인 1.1.17 / native 1.1.13**입니다. 업데이트 토큰 입력·저장·사용 기능을 제거하고 기존 CustomVoice 업데이트 토큰 파일도 정리합니다.
- 플러그인은 native 연결 없이 공개 GitHub raw 파일을 받습니다. 통화 중에도 확인·다운로드하며 적용만 통화 종료까지 미룹니다. 연결 오류 상태에 머물러 업데이트가 영구 대기하는 문제도 수정했습니다.
- native는 GitHub 최신 정식 릴리스에서 자동 다운로드하고 Discord 완전 종료 후 설치합니다. 공개 다운로드 주소를 사용하므로 GitHub API 요청 한도에 의존하지 않습니다.
- 전체 패키지를 적용할 때 오래된 플러그인도 함께 갱신합니다. 설치된 플러그인이 더 새 버전이면 유지합니다. 기존 설정은 보존합니다.
- 이전 버전에서 자동 업데이트가 멈췄다면 이번 전체 ZIP 설치가 한 번 필요할 수 있습니다. 설치 후에는 별도 토큰이나 업데이트 버튼 없이 동작합니다.

## 1.1.16 알탭 중 게임 프레임 캡처

- **플러그인 1.1.16 / native 1.1.12**입니다. 송출자는 전체 ZIP 설치 후 Discord를 완전히 재시작해야 합니다. 시청자 자동 복구는 1.1.15 이상을 유지합니다.
- 공유한 창이 활성 전체화면으로 감지되면 게임 렌더링 후크를 연결합니다. 연결 후에는 알탭·최소화 여부로 캡처 경로를 전환하지 않고, 같은 게임의 GPU 프레임을 계속 받습니다. 게임을 한 번 활성화해야 최초 연결이 시작됩니다.
- OBS Studio 32.0.4의 공식 게임 캡처 구성요소를 포함합니다. Discord의 내부 모듈을 재사용하는 기능은 아니며 OBS 앱 설치·실행은 필요 없습니다. 32/64비트 게임, GPU 공유 및 메모리 호환 경로, 버퍼 교체·해상도 변경, OpenGL 상하 반전을 처리합니다. 소리는 계속 선택한 앱 프로세스만 캡처합니다.
- 게임 캡처는 선택한 창과 같은 루트 창의 프레임만 받습니다. 다른 OBS 호환 프로그램이 캡처를 소유하면 이를 중단하거나 변경하지 않습니다. 방송을 끄면 캡처 중지 신호를 보내고 핸들을 정리합니다. 후크 DLL 자체는 OBS의 설계에 따라 게임 종료 때까지 로드될 수 있습니다.
- 게임 후크가 차단되거나 15초 동안 초기 프레임이 없으면 알림 후 기존 캡처 경로를 사용합니다. 이 경우나 게임 자체가 렌더링을 중단하는 경우에는 백그라운드 움직임을 보장하지 않습니다. Vulkan 시스템 레이어는 설치하지 않습니다.
- 방송 정보에 **게임 캡처 · GPU / 호환 모드**를 표시합니다. 후크 프로토콜에는 고유 프레임 번호가 없어 캡처 FPS는 버퍼 샘플링 횟수이며, 게임의 실제 렌더링 FPS와 다를 수 있습니다. 송출 FPS는 별도의 WebRTC 통계입니다.
- 합성 GPU/공유 메모리에서 연속 프레임 변경, 다른 창 차단, 버퍼 교체, 픽셀 변환·상하 반전을 검증했습니다. **실제 osu! 후크 연결·알탭·두 PC 송수신은 미확인**입니다. computer-use와 실제 게임 조작은 수행하지 않았습니다.
- 구성요소의 라이선스·완전한 대응 소스는 `CustomVoice.native/game-hook`에 동봉합니다.

## 1.1.15 알탭 화면 유지 · 시청 영상 자동 복구

- **플러그인 1.1.15 / native 1.1.11**입니다. 송출자와 시청자 모두 1.1.15로 업데이트해야 아래 송출·수신 개선이 함께 적용됩니다. 전체 ZIP 설치 후 Discord를 완전히 재시작해 주세요.
- 알탭·최소화로 게임이 새 프레임을 주지 않으면 검은 화면 대신 **마지막으로 정상 송출한 게임 프레임**을 유지합니다. 창 상태 확인을 통과하지 못한 준비 중 프레임은 저장하지 않습니다. 게임이 돌아오면 새 프레임으로 교체합니다.
- 대기 중 화질을 변경해도 저장한 영상을 GPU에서 크기 조절해 유지합니다. 송출 모니터에는 **마지막 게임 화면 유지 중 · 새 화면 대기**를 표시합니다. 게임 자체가 최소화되어 렌더링을 멈춘 동안 새로운 게임 영상을 만들어내는 기능은 아닙니다.
- 시청자에서는 실제 수신 바이트·디코딩 프레임·표시 프레임을 확인합니다. 데이터가 들어오는데 디코딩이 8초간 멈추면 영상 구독을 다시 연결하고, 디코딩은 진행되지만 표시만 멈추면 플레이어를 다시 연결합니다.
- 수신 구독 복구는 영상에만 적용하며 음성과 시청 선택을 유지합니다. 중복 요청, 이전 방송, 채널 이동·시청 종료 뒤의 재구독을 막습니다. 복구 요청은 최소 15초 간격, 1분에 최대 3회로 제한합니다. 숨겨진 화면·정상적인 정지 화면·서버의 일시정지는 복구 대상으로 삼지 않습니다.
- 송출 FPS는 송신자의 수치입니다. 시청자 수신·디코딩 로그를 별도로 남기며 송출 FPS만으로 수신 성공을 판단하지 않습니다.
- 합성 GPU 픽셀 검증, 수신 통계 모형, 재구독 이벤트·취소 테스트를 사용했습니다. 실제 osu!와 두 PC 사이 송수신은 미확인입니다.

## 1.1.14 게임 복귀 후 송출 FPS 복구

- **플러그인 1.1.14 / native 1.1.10**입니다. 전체 ZIP 설치 후 Discord를 완전히 재시작해야 합니다.
- 최소화된 게임의 WGC 크기 `160×28`을 초기 인코딩 크기로 사용하던 경로를 수정했습니다. 최소화 상태에서는 해당 모니터 크기로 대기 프레임을 준비하고 실제 게임 프레임이 오면 크기를 갱신합니다. 정상적으로 작은 앱 창은 그대로 캡처합니다.
- 캡처 전환·최소화로 화면이 없는 경우를 인코더 과부하로 세지 않습니다. 새 화면을 받으면 native와 renderer의 처리 속도를 목표 FPS로 복구하고, 전환 직전의 0 FPS 샘플은 두 번 건너뜁니다. 실제 인코더 과부하에 대한 속도 조절은 유지합니다.
- 게임 화면을 받을 수 없는 동안에는 자체 검은 GPU 프레임을 낮은 FPS로 보내 연결을 유지합니다. 전체 화면에서 벗어나면 이전 모니터 화면을 다시 보내지 않으며 FPS 표시창에 **게임 화면 대기 중**을 표시합니다.
- 실제 화면을 캡처하지 않는 합성 GPU 검증에서 배포 코드의 대기→실제 프레임→대기 전환을 반복하고, 픽셀 교체와 1→165 FPS 처리 속도 복구를 확인했습니다. 실제 osu! 송출은 아직 확인하지 않았습니다.

## 1.1.13 공유할 앱 목록의 게임 누락 보완

- **플러그인 1.1.13 / native 1.1.9**입니다. 전체 ZIP 설치 후 Discord를 완전히 재시작해야 새 창 목록 기능이 적용됩니다.
- 기존 Discord 목록에 Windows의 최상위 앱 창 목록을 합칩니다. Discord로 전환할 때 최소화된 게임이나 미리보기 이미지를 얻지 못한 창도 선택할 수 있습니다. 같은 창은 HWND 기준으로 합치고 기존 미리보기를 유지합니다.
- 공유 대상 선택창에 **목록 새로고침**을 추가했습니다. 선택창을 연 뒤 실행한 게임도 다시 조회할 수 있으며, 최소화된 창은 공유 후 게임으로 돌아가라는 안내를 표시합니다.
- 숨긴 창, 다른 가상 데스크톱 등 DWM에서 가린 창, 도구 창, 캡처 제한 창은 보완 목록에서 제외합니다. 실제 캡처는 사용자가 선택한 HWND로 시작하며 앱 오디오도 같은 창을 기준으로 합니다.
- 창 목록 조회는 5초 제한을 두고 중복 요청을 합칩니다. 실패 시 기존 Discord 목록을 유지하며 로그에는 창 제목 대신 수집 개수와 오류를 기록합니다.
- 창 상태 모형, 가짜 IPC 및 메모리 DOM으로 누락 보완·중복 제거·새로고침·취소를 검증합니다. computer-use, 실제 창 열거 및 osu! 조작은 수행하지 않았습니다.

## 1.1.12 게임 창 공유 시작 오류 수정

- **플러그인 1.1.12 / native 1.1.8**입니다. 전체 ZIP을 설치하고 Discord를 완전히 재시작해야 캡처 수정이 적용됩니다.
- 제목 표시줄을 제외할 때 오른쪽·아래쪽 좌표를 `RectI`의 너비·높이 인자로 넘기던 오류를 수정했습니다. 잘라낼 영역이 원본 프레임 밖으로 커지면서 공유 시작 단계의 GPU 변환이 `0x80070057 / E_INVALIDARG`로 실패할 수 있었습니다.
- 클라이언트 영역을 원본 크기 안으로 제한하고 GPU 설정 전 검증합니다. 영상 변환 실패 시 원본·영역·출력 크기를 오류에 함께 남깁니다.
- 창 영역, 전체 화면, 홀수 크기, 경계 밖 영역을 검증했습니다. 화면을 캡처하지 않는 합성 GPU 프레임에서 이전 코드의 동일 HRESULT를 재현했고 수정 후 변환을 확인했습니다. 실제 osu! 및 Discord 조작은 수행하지 않았습니다.
- 기존 시청자 목록, 전체 화면 자동 전환, 앱별 소리 기능을 유지합니다.

## 1.1.11 시청자에게도 방송별 시청자 목록 표시

- 방송자뿐 아니라 **방송을 보는 사람도 인원수와 닉네임 목록**을 확인할 수 있습니다. 시청자 본인에게는 `(나)`를 표시합니다. 방송자 본인과 미리보기만 보는 사람은 인원수에 포함하지 않습니다.
- 방송자가 집계한 목록을 실제 시청을 알린 참여자에게 전달합니다. 시청 시작·종료·퇴장 시 갱신하고, 여러 방송을 동시에 시청하면 각 방송의 목록을 따로 표시합니다. 음성 연결 패널에는 표시하지 않습니다.
- 해당 방송자가 보낸 현재 방송의 목록만 수신합니다. 이전 방송·이전 연결의 목록과 오래된 순번은 무시하며, 재접속이나 새 방송 시작 시 이전 목록을 정리합니다.
- 첫 목록을 기다리는 동안에는 **시청자 확인 중**, 구버전 방송자나 응답 중단으로 목록을 받지 못하면 **시청자 확인 불가**로 표시합니다. 서버 권한 차단 안내도 유지합니다.
- 시청 화면에서 목록을 확인하려면 **방송자와 목록을 보려는 사용자 모두 1.1.11 이상**이 필요합니다. 1.1.8~1.1.10 시청자의 기존 시청 알림도 집계에 포함합니다.
- 서버에서 방송자와 시청자의 `canPublishData: true` 권한이 필요합니다. 새 서버 API는 필요하지 않으며 기존 [서버 권한 수정 안내](SERVER-VIEWERS.md)가 그대로 적용됩니다.
- 1.1.10의 캡처 변경과 native 1.1.7을 유지합니다. 메시지 교환을 재현한 다중 클라이언트 테스트와 코드 회귀 검증을 수행했으며, computer-use나 실제 Discord 조작은 하지 않았습니다.

## 1.1.10 자동 전체 화면 캡처 · 제목 표시줄 제외

- **플러그인 1.1.10 / native 1.1.7** 조합입니다. 별도 옵션 없이 선택한 애플리케이션 창의 상태를 자동으로 구분합니다.
- 일반 창은 WGC로 캡처하되 Windows의 클라이언트 영역만 GPU에서 잘라냅니다. Windows 제목 표시줄과 바깥 테두리를 제외합니다. 앱이 클라이언트 영역 안에 직접 그린 탭·메뉴 등은 앱 화면의 일부로 남습니다.
- 선택한 창이 활성화되어 한 모니터를 채우는 전체 화면·보더리스 상태이면 DXGI Desktop Duplication으로 자동 전환합니다. 소리는 기존의 선택한 앱 프로세스 트리 캡처를 유지하며 시스템 소리로 전환하지 않습니다.
- 전체 화면 경로는 **모니터 영상**이므로 화면 위 알림·오버레이가 함께 보일 수 있습니다. 공유 선택창에도 안내합니다. 알탭·최소화·창모드 전환을 감지하면 모니터 프레임 수집을 중지하고 선택 창 캡처로 돌아갑니다.
- 모드 전환으로 복제 연결이 무효화되면 간격을 두고 재연결하며, 선택 창이 없어지거나 HWND가 다른 프로세스에 재사용되면 캡처를 중지합니다. 선택한 모니터가 다른 GPU로 이동한 경우나 회전된 모니터는 안내 후 공유를 다시 시작해야 하거나 지원이 제한됩니다.
- 최소화된 게임이 새 프레임을 주기 전에는 자체 검은 GPU 화면으로 공유를 시작합니다. 소스 변경과 출력 프레임 재사용을 구분하는 진단 정보도 기록합니다.
- 모드 전환·제목 표시줄 제거에 따른 해상도 변경을 출력 GPU 표면에도 반영합니다. 창 내부 영역을 찾지 못했을 때 제목 표시줄을 포함한 전체 창으로 임의 대체하지 않습니다.
- 전체 동작에는 새 native와 Discord 완전 재시작이 필요합니다. 이 수정은 송출자에게 적용하며 시청자 업데이트는 필수가 아닙니다. 기존 1.1.9의 UI·시청자·오디오 변경을 유지했습니다.
- 실행 테스트와 computer-use 없이 소스 수정 및 배포용 빌드만 수행했습니다. 실제 osu! 환경에서 정지 증상이 해소되었는지는 아직 확인하지 않았습니다.

DXGI 모드 전환 처리 근거: [Microsoft AcquireNextFrame 문서](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutputduplication-acquirenextframe).

## 1.1.9 시청자 표시 위치와 서버 권한 안내

- 음성 연결 패널의 시청자 표시를 제거했습니다. 내 방송 화면에서만 시청자 목록을 표시합니다.
- 현재 서버의 LiveKit 접속 권한에서 `canPublishData: false`를 확인했습니다. 이 상태에서는 1.1.8끼리도 시청 알림이 서버에서 버려져 집계가 되지 않습니다. 플러그인 업데이트만으로 서버 권한을 바꿀 수는 없습니다.
- 서버가 모든 상대의 시청 알림을 막으면 **시청자 확인 불가**, 일부 상대만 막으면 **확인된 시청자 N명**으로 표시합니다. 집계 불가를 시청자 0명으로 표시하지 않습니다.
- 차단된 전송을 반복하지 않고 권한 상태만 로그에 남깁니다. 서버에서 권한을 변경했을 때 시청 상태를 즉시 다시 알리고, 권한이 취소된 참여자의 오래된 표시는 정리합니다.
- 서버 토큰 발급부에서 `canPublishData`를 허용하고 참여자가 채널에 다시 입장해야 실제 집계가 작동합니다. 전달용 수정 안내: [SERVER-VIEWERS.md](SERVER-VIEWERS.md). 양쪽 플러그인은 1.1.8 이상이면 됩니다. native는 1.1.6을 유지합니다.
- 컴퓨터 제어 없이 코드 회귀 검증을 수행했습니다. 실행 중인 Discord에 수정본을 설치하거나 서버를 변경하지 않았습니다.

## 1.1.8 시청자·미리보기·Discord UI·오디오 개선

- 내 방송 화면과 음성 연결 패널에 **시청자 N명** 목록을 추가했습니다. 실제 방송 영상에 구독한 사람만 집계하며 닉네임 미리보기는 제외합니다. **방송자와 시청자 모두 1.1.8 이상**이어야 목록에 표시됩니다. 시청 종료·연결 종료·새 방송 시작 시 정리하며, 예기치 않은 연결 손실은 약 35~45초 뒤 목록에서 만료됩니다.
- 방송 닉네임에 마우스를 올리면 미리보기를 표시하고, **닉네임을 클릭하면 미리보기가 고정**됩니다. 미리보기로 마우스를 옮겨도 유지되며 아래 **방송 보기** 버튼으로 시청할 수 있습니다. 닫기 버튼, 바깥 클릭 또는 Esc로 닫습니다. 프로필은 닉네임 우클릭 메뉴에서도 열 수 있습니다.
- Discord 채널 목록의 폰트를 따라가고 닉네임·아바타·음소거·LIVE 표시를 일정한 행과 열에 배치했습니다. 긴 닉네임의 말줄임, 한글/영문 기준선, 방송/설정 화면의 글꼴·버튼·간격을 정리했습니다.
- 자체 합성 효과음을 제거하고 Discord의 입장/퇴장, 음소거/해제, 헤드셋 차단/해제, 방송 시작/종료 효과음을 재사용합니다. 기본 재생 엔진을 우선 사용하고 엔진을 찾지 못하면 Discord에 포함된 동일한 음원으로 재생합니다. 별도 효과음 볼륨 대신 Discord 출력 볼륨을 따릅니다. 재접속과 음소거/헤드셋의 동시 변경에서 중복 재생을 막습니다.
- 방송 소리는 스테레오 128 kbps 설정으로 전송하고 음성 전용 무음 전송 중단을 해제했습니다. 100% 초과 수신 볼륨은 Web Audio로 처리하여 HTML 오디오 볼륨 범위 초과 오류와 중복 재생을 막고, 마이크/방송 볼륨 분리를 유지합니다.
- 재시청 시 이미 구독된 소리 트랙을 다시 연결하고, 방송 보기를 누르는 시점에 오디오 재생을 재개합니다. 출력 장치 확인 중 시청을 종료한 트랙이 뒤늦게 재생되지 않도록 했습니다.
- 소리 캡처 실패 시 **다음 방송의 소리 공유 설정**과 **현재 실제 송출 상태**를 구분합니다. 창 공유의 앱 오디오 실패 시 시스템 전체 소리로 전환하지 않습니다. 앱 오디오 처리 중단은 복구를 시도하며 복구할 수 없으면 캡처를 정리하고 안내합니다.
- 4:3/카메라 관련 동작은 변경하지 않았습니다. native는 1.1.6을 그대로 사용합니다.

## 1.1.7 화면공유 소리 안내

- 방송 설정의 잘못된 이름인 **시스템 소리 공유**를 **공유 대상 소리**로 수정했습니다. 공유 대상 선택창과 플러그인 설정도 같은 이름과 설명을 사용합니다.
- **앱·게임 창 공유**에서는 선택한 앱과 자식 프로세스의 소리를 보냅니다. 같은 프로세스가 여러 창·탭을 담당하면 그 소리도 함께 포함될 수 있습니다.
- **전체 화면 공유**에서는 다른 앱과 알림을 포함한 시스템 소리를 보냅니다.
- 이 옵션을 끄면 앱 소리도 방송에 보내지 않습니다. 마이크 음소거는 별도로 조절합니다.
- 소리 캡처 방식과 기존 켜기/끄기 설정은 유지합니다. native는 1.1.6을 그대로 사용합니다.

## 1.1.6 공개 저장소 업데이트

- 공개 저장소에서 플러그인과 native를 받을 때 GitHub 토큰을 필수로 요구하던 처리를 제거했습니다. 1.1.17에서 선택적 토큰 기능도 제거했습니다.
- 이전에 전달한 1.1.5와 구분하고 native 업데이트가 감지되도록 1.1.6으로 배포합니다. 1.1.4 앱별 오디오와 1.1.5 업데이트 수정이 모두 포함됩니다.
- 실행 테스트 없이 배포용 빌드만 진행했습니다.

## 1.1.5 업데이트 안정성 보완

- 플러그인은 시작 후와 1시간마다 자동 확인합니다. 통화·방송 중에는 30초 간격으로 연결 상태만 확인하고, 종료 후 다운로드/적용을 다시 시도합니다. 실패 시 재시도 간격은 1분부터 최대 15분까지 늘어납니다.
- 1.1.5 native와 함께 사용하면 GitHub 커밋이 바뀌지 않았을 때 큰 플러그인 파일을 다시 다운로드하지 않습니다. 통화 때문에 잠깐 보류한 소스는 최대 1분만 보관합니다.
- 다운로드한 JS는 실행하지 않고 문법을 먼저 파싱합니다. 오류가 있으면 현재 파일을 유지합니다. 실제 기록 결과가 다르면 백업으로 복원하며, 플러그인 이름 변경·강제 비활성화/활성화는 하지 않습니다. 문법 검사는 실행 중 발생하는 오류까지 보장하지 않습니다.
- 플러그인을 끄거나 재시작한 뒤 이전 다운로드 결과가 적용되지 않도록 기존 실행 세대 확인을 유지했습니다. 요청 제한·GitHub 서버 오류 메시지를 구분합니다.
- native 준비 작업과 설치 작업 사이에 다른 Discord 창이 중복 예약할 수 있던 구간을 차단했습니다. 상태 파일 손상과 이전 작업 중단 시에도 새 요청으로 재시도할 수 있습니다.
- 설정창은 설치된 버전, 실제 로드된 버전의 재시작 필요 여부와 배포된 버전을 구분합니다. 과거 설치 기록이 새 버전 안내를 덮어쓰지 않으며, 필요한 native가 아직 정식 배포되지 않았을 때 전체 ZIP 설치를 안내합니다.
- native 대기 상태 조회는 10초 간격으로 줄이고 겹친 요청을 합칩니다. 이전 다운로드 임시 폴더는 활성 작업이 없을 때만 정리하며, 최근 두 개와 최근 7일 자료 및 설치 백업은 유지합니다.
- native 재사용 패키징은 실제 빌드 버전과 메타데이터가 다르면 중단합니다. native 수동 업데이트는 플러그인 JS를 덮어쓰지 않습니다.
- 기존 1.1.4 오디오 수정도 포함됩니다. 전체 개선 적용에는 플러그인/native 1.1.5가 필요합니다. 실행 테스트 없이 배포용 ZIP을 빌드했습니다.

## 1.1.4 앱별 오디오 경로 보완

- 애플리케이션/창을 선택한 공유는 창모드·보더리스 모두 선택한 프로세스와 자식 프로세스의 오디오만 캡처합니다.
- 시스템 루프백은 전체 화면(`screen:`)을 명시적으로 선택한 경우에만 사용합니다. 창 식별 불가·앱 오디오 실패 시에는 시스템 소리로 대체하지 않습니다.
- 오디오를 최신 패킷 하나로 덮어쓰던 처리를 최대 100ms의 순서 있는 큐로 변경하고, 오디오 처리기가 받은 뒤 다음 묶음을 전달합니다.
- 오디오 처리 스레드 준비를 기다리고, 출력이 무음인 연결을 통해 렌더링이 유지되도록 했습니다. 캡처 소리를 로컬 스피커로 재생하지 않습니다.
- 게임 프로세스 종료 감시에 불필요했던 프로세스 핸들 접근을 제거하고 선택 창/PID를 감시합니다. UWP 프레임은 해당 창 내부의 앱 프로세스를 사용합니다.
- 앱의 상위 런처나 다른 프로세스를 임의로 추가하지 않습니다. 다만 같은 프로세스를 공유하는 여러 창/탭의 소리는 프로세스 단위로 묶일 수 있습니다.
- 실패 단계·캡처 프레임 수·오디오 처리 프레임 수는 기존 로그 폴더에 기록합니다. 음성 내용은 파일로 저장하지 않습니다.
- 이 패치는 **송출자 PC의 플러그인과 native를 함께 1.1.4로 교체**해야 모두 적용됩니다. 시청자 업데이트는 이 오디오 수정의 필수 조건이 아닙니다.
- 문제가 발생한 PC의 로그를 받지 못했으며, 요청에 따라 실행 검증·테스트 없이 코드 수정과 배포용 빌드만 진행했습니다.

## 1.1.3 자동 업데이트 복구

- BetterDiscord에서 지원하지 않는 `fs.openSync` 호출 때문에 업데이트 파일 교체가 실패하던 문제를 수정했습니다.
- 지원되는 `writeFileSync`로 기존 파일을 덮어쓰며, 백업과 실패 시 복원 처리를 유지합니다.
- 1.1.2의 썸네일 변경을 포함합니다. native는 기존 1.1.1을 사용합니다.
- 이 오류가 발생하는 기존 설치본은 수정된 플러그인 파일을 한 번 직접 교체해야 합니다. 고장 난 업데이터 자체는 자동으로 복구할 수 없습니다.
- 이번 수정에서는 실행 검증·테스트를 수행하지 않았습니다.

## 1.1.2 첨부본 반영

- 제공된 `CustomVoice.plugin.js`를 개발 및 배포 기준 파일로 반영했습니다.
- 방송 썸네일을 서버 API로 전달하고 로그인한 사용자가 음성채널 접속 없이 조회하는 코드입니다.
- 서버에 `POST /api/v1/screenshare/preview`, `DELETE /api/v1/screenshare/preview`, `GET /api/v1/screenshare/previews/:mediaIdentity` 구현이 필요합니다.
- 미리보기 편집 원본 `native/voice-extras.js`도 첨부본과 동기화했습니다. native 요구 버전은 1.1.1입니다.
- 이번 반영에서는 실행 검증·테스트 및 서버 배포를 수행하지 않았습니다.

## 1.1.0 변경 사항

- 자신과 같은 채널 사용자의 접속·퇴장 효과음.
- 자신의 마이크/헤드셋 음소거 토글 및 방송 시작·종료 효과음. 설정에서 끄거나 볼륨을 조절할 수 있습니다.
- 방송 유저에게 마우스를 올리거나 유저를 클릭하면 썸네일을 표시합니다.
  같은 음성 채널에서 작동하며 송출자와 시청자 모두 1.1.0이 필요합니다.
  실제 시청 구독이나 오디오 재생 없이 요청한 상대에게 작은 JPEG만 전송합니다.
- 창 공유의 소리는 선택 창의 프로세스 및 자식 프로세스만 캡처합니다.
  실패하면 화면만 공유하며 전체 시스템 소리로 대체하지 않습니다.
  같은 프로세스 트리의 여러 창/탭 소리는 함께 포함될 수 있습니다.
  전체 화면 공유에서 소리를 켜면 시스템 소리를 사용합니다.
- 시청 화면에서 마우스가 나가면 채널명/화질 UI를 숨깁니다. 키보드 조작 중에는 접근성을 유지합니다.
- 연결 해제 시 캡처 트랙, 프로세스 오디오, 시청 구독과 재생 요소를 즉시 정리합니다.
- 시작 직후 업데이트를 지연하고 파일을 제자리에서 교체해 BetterDiscord가 플러그인을 삭제된 것으로 처리하는 문제를 방지합니다.

## GitHub 업데이트

공개 저장소 `awizc/CustomVoice-plugin`에서 계정이나 토큰 없이 자동 업데이트합니다.
플러그인은 시작 3.5초 후와 5분마다 `raw.githubusercontent.com`에서 확인합니다.
통화·방송 중에도 새 버전을 내려받고 적용만 미룹니다. 종료 후 30초 이내에 적용합니다.
연결 오류만 남아 있고 실제 통화가 없으면 업데이트를 계속 진행합니다.
다운로드 파일의 이름·버전·문법을 확인하고, 기존 파일을 백업한 뒤 교체합니다. 쓰기 실패 시 복원합니다.

native 구성요소는 시작 12초 후와 15분마다 GitHub 최신 정식 릴리스를 확인하고 자동 다운로드합니다.
ZIP의 SHA-256과 구성 파일을 검증한 뒤 Discord 완전 종료를 기다립니다. 실행 중인 Discord는 강제 종료하지 않습니다.
Discord를 트레이에서 완전히 종료하고 5초 정도 기다렸다가 다시 실행하세요.
전체 패키지에 더 새 플러그인이 있으면 함께 설치하며, 이미 더 최신인 플러그인과 사용자 설정은 보존합니다.
예약은 최대 24시간 유지되며 중단·실패 시 자동 재시도합니다. 설정에서도 확인·재시도할 수 있습니다.

업데이트 토큰 입력란·저장 API·인증 헤더는 제거했습니다. 이전 CustomVoice 전용 토큰 파일은 정리합니다.
이전 버전의 업데이트가 멈췄다면 최신 전체 ZIP을 한 번 설치하세요. 이후에는 자동으로 업데이트됩니다.

## 개발 및 패키지 생성

개발 PC에는 .NET 9 SDK와 Node.js가 필요합니다.

```powershell
.\package.ps1 -Dotnet dotnet -SkipCapabilityCheck
```

`native/sync-renderer.cjs`가 native 캡처 및 기능 모듈을 배포용 `CustomVoice.plugin.js`에 반영합니다.
`native/plugin-updater.js`, `native/process-audio.js`, `native/voice-extras.js`, `native/broadcast-viewers.js`, `native/screen-recovery.js`, `native/discord-theme.js`가 신규 기능의 편집 원본입니다.
생성물은 `dist/CustomVoice-<버전>-windows-x64.zip`입니다.
릴리스를 배포할 때 같은 빌드에서 생성한 `dist/CustomVoice-native.json`도 ZIP과 함께 업로드합니다.
이 파일은 native 버전과 ZIP의 SHA-256을 담습니다. 태그는 `v<플러그인 버전>` 형식이며 정식 최신 릴리스만 사용합니다.
플러그인만 변경한 릴리스에서는 `@nativeVersion`과 native 버전을 유지하고 `-ReuseNativeBuild`로 패키징합니다.
native 변경 시 `@nativeVersion`, host/preload 버전, `NativeUpdate.CurrentVersion`을 함께 올립니다.
1.1.8은 native 1.1.6 빌드를 재사용합니다. 시청자/효과음, 오디오 출력, 화면 공유 캡처/종료 회귀 검증과 별도의 숨겨진 Electron 창에서 미리보기 클릭·닫기·시청 버튼·닉네임 정렬을 확인했습니다. 합성 스테레오 PCM을 실제 AudioWorklet과 로컬 WebRTC 연결로 보내 수신 파형과 종료 정리를 확인했습니다. 실제 Discord의 효과음 모듈과 여러 PC 사이의 시청자 표시·게임 소리 전달은 실사용 검증이 필요합니다.

`tests/ui-audio-smoke.cjs` 실행에는 `native/smoke`의 Electron과 `dist/ui-check`의 React/React DOM이 필요합니다. 테스트는 자체 숨김 창과 테스트 프로필만 사용하며 실제 마이크, 시스템 소리, Discord 창은 사용하지 않습니다.

`dotnet run --project tests/capture-geometry/CaptureGeometry.Tests.csproj -c Release`는 캡처 영역 계산을 검증합니다. 끝에 `-- --gpu`를 추가하면 자체 합성 텍스처로 BGRA→NV12 변환도 검증합니다. GPU 검증은 Windows 하드웨어 영상 처리 지원이 필요하며 실제 화면이나 앱을 캡처하지 않습니다.

`node --test tests/source-list.test.cjs`와 `dotnet run --project tests/window-sources/WindowSources.Tests.csproj -c Release`는 실제 데스크톱에 접근하지 않고 창 목록·선택창 갱신 동작을 검증합니다.

`dotnet run --project tests/capture-recovery/CaptureRecovery.Tests.csproj -c Release`는 배포 native의 GPU 변환·복구 메서드를 합성 텍스처로 검증합니다. 캡처 생성자를 실행하지 않으며 실제 창·WGC 세션·DXGI 화면 캡처를 사용하지 않습니다. Windows GPU 영상 처리 지원이 필요합니다.

로그: `%APPDATA%/BetterDiscord/plugins/logs/CustomVoice`.
native 구성과 서드파티 고지는 `native/README.txt`, `native/THIRD-PARTY-NOTICES.txt`, `native/licenses`를 참고하세요.
프로세스 오디오 구현은 Microsoft의 [ApplicationLoopback API 예제](https://github.com/microsoft/Windows-classic-samples/tree/main/Samples/ApplicationLoopback)를 참고했습니다.
